# Azure Monitoring and Management

Azure monitoring services help you understand resource health, performance, logs, alerts, and application behavior. For interviews, focus on metrics vs logs, alerts, diagnostic settings, Log Analytics, and Application Insights.

## 1. Azure Monitor

Azure Monitor is the main monitoring platform in Azure.

### What Azure Monitor collects
- Metrics
- Logs
- Activity logs
- Diagnostic logs
- Application telemetry

### Interview point
- Azure Monitor is the central place for monitoring Azure resources and applications.

## 2. Log Analytics Workspace

A Log Analytics Workspace stores log data and allows queries using KQL.

### Used for
- Centralized log collection
- Troubleshooting
- Security analysis
- Alert queries
- Dashboards and workbooks

### Interview point
- Logs are stored in a workspace and queried using KQL.

## 3. Application Insights

Application Insights monitors application performance and failures.

### Tracks
- Requests
- Dependencies
- Exceptions
- Response time
- Availability tests
- User behavior

### Interview point
- Use Application Insights for application-level monitoring, not only infrastructure monitoring.

## 4. Alerts and Action Groups

Alerts notify teams when a condition is met.

### Alert parts
- Signal: metric or log query
- Condition: threshold or query result
- Scope: resource being monitored
- Action group: notification or automation action

### Action group examples
- Email
- SMS
- Webhook
- Azure Function
- ITSM integration

## 5. Metrics vs Logs

### Metrics
- Numeric time-series data
- Fast and lightweight
- Good for CPU, memory, request count, and availability

### Logs
- Detailed event records
- Good for troubleshooting and investigation
- Queried using KQL

### Interview point
- Metrics answer "what changed"; logs help explain "why it changed."

## 6. Diagnostic Settings

Diagnostic settings send platform logs and metrics to destinations.

### Destinations
- Log Analytics Workspace
- Storage account
- Event Hub

### Interview point
- Many resources need diagnostic settings enabled before detailed logs are available.

## 7. Azure Service Health

Azure Service Health shows Azure platform incidents, planned maintenance, and health advisories.

### Interview point
- Use Service Health to check whether an issue is caused by an Azure platform incident.

## 8. Azure Advisor

Azure Advisor gives recommendations for cost, security, reliability, performance, and operations.

## Hands-On Practice

Use existing practice resources such as a VM, App Service, or storage account.

### 1. Create a Log Analytics Workspace

Steps:
1. Search for `Log Analytics workspaces`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. Name: `law-practice-dev`
5. Region: same as your resources
6. Create the workspace

### What to observe
- A workspace stores logs from many Azure resources
- Workspace region and retention settings affect cost

### 2. Enable Diagnostic Settings

Steps:
1. Open a storage account or App Service
2. Select `Diagnostic settings`
3. Add a diagnostic setting
4. Select useful log categories
5. Send logs to `law-practice-dev`
6. Save

### What to observe
- Logs may take a few minutes to appear
- Without diagnostic settings, detailed platform logs may be missing

### 3. Create a Metric Alert

Steps:
1. Open a VM, App Service, or storage account
2. Select `Alerts`
3. Create an alert rule
4. Choose a metric such as CPU percentage or availability
5. Set a threshold
6. Create an action group with your email
7. Save the alert

### What to observe
- Alerts need a scope, condition, and action
- Alert rules can create cost depending on type and frequency

### 4. Query Logs with KQL

Steps:
1. Open `law-practice-dev`
2. Select `Logs`
3. Run a basic query after logs arrive

Example:

```kusto
AzureActivity
| take 10
```

### What to observe
- KQL is used to search and filter logs
- Logs are useful for root cause analysis

### 5. Review Service Health and Advisor

Steps:
1. Search for `Service Health`
2. Review active service issues
3. Search for `Advisor`
4. Review recommendations

### 6. Clean Up

Steps:
1. Delete alert rules
2. Delete diagnostic settings if not needed
3. Delete the Log Analytics Workspace if created only for practice

## Common Interview Questions

- What is the difference between metrics and logs?
  Answer:
  Metrics are numeric time-series values. Logs are detailed records used for deeper troubleshooting.

- What is a Log Analytics Workspace?
  Answer:
  It is a central place to store and query logs using KQL.

- What is an action group?
  Answer:
  An action group defines who or what gets notified when an alert fires.

## Final Tip

For monitoring scenarios, explain the flow: enable diagnostics, collect data, query logs or metrics, create alerts, and investigate root cause.
