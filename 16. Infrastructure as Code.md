# Infrastructure as Code

Infrastructure as Code, or IaC, means defining cloud infrastructure using code instead of manual portal steps. For interviews, focus on repeatability, version control, review, automation, and environment consistency.

## 1. ARM Templates

ARM templates are JSON files used to deploy Azure resources.

### Key points
- Native Azure deployment format
- Declarative
- Supports parameters and variables
- Can be used in pipelines

### Interview point
- ARM templates are powerful but JSON can become verbose.

## 2. Bicep

Bicep is a simpler language for Azure IaC that compiles to ARM templates.

### Why use Bicep
- Cleaner syntax than ARM JSON
- Native Azure support
- Supports modules
- Good for Azure-only environments

### Interview point
- Bicep is commonly preferred over raw ARM templates for Azure-native IaC.

## 3. Terraform

Terraform is a multi-cloud IaC tool.

### Key points
- Uses HCL language
- Maintains state
- Supports Azure through provider plugins
- Works across many cloud platforms

### Interview point
- Terraform is useful when teams need multi-cloud or tool standardization.

## 4. Parameter Files

Parameter files separate environment-specific values from reusable templates.

### Examples
- VM size
- Region
- Resource names
- Environment tags
- SKU choices

## 5. Reusable Modules

Modules package common infrastructure patterns.

### Used for
- VNets
- Storage accounts
- App Services
- AKS clusters
- Monitoring setup

## 6. Environment-Based Deployments

IaC supports consistent dev, test, and production deployments.

### Example
- Same template
- Different parameter files
- Different approvals
- Different resource sizes

## Hands-On Practice

Use Azure CLI with Bicep for a simple resource group deployment.

### 1. Install or Confirm Azure CLI

Command:

```bash
az version
```

### 2. Login to Azure

Command:

```bash
az login
```

### 3. Create a Resource Group

Command:

```bash
az group create --name rg-iac-practice-dev --location centralindia
```

### 4. Create a Simple Bicep File

Create `main.bicep` for practice:

```bicep
param location string = resourceGroup().location
param storageName string

resource storage 'Microsoft.Storage/storageAccounts@2023-01-01' = {
  name: storageName
  location: location
  sku: {
    name: 'Standard_LRS'
  }
  kind: 'StorageV2'
}
```

### 5. Deploy the Bicep File

Command:

```bash
az deployment group create --resource-group rg-iac-practice-dev --template-file main.bicep --parameters storageName=<unique-storage-name>
```

### What to observe
- The same file can be reused
- Parameters make deployments flexible
- Deployment history is visible in the resource group

### 6. Clean Up

Command:

```bash
az group delete --name rg-iac-practice-dev --yes
```

## Common Interview Questions

- What is Infrastructure as Code?
  Answer:
  IaC defines infrastructure using code so resources can be deployed repeatedly, reviewed, versioned, and automated.

- What is the difference between ARM, Bicep, and Terraform?
  Answer:
  ARM is Azure's native JSON template format. Bicep is a simpler Azure-native language that compiles to ARM. Terraform is a multi-cloud IaC tool that uses state.

- Why use parameter files?
  Answer:
  Parameter files separate environment-specific values from reusable templates.

## Final Tip

In interviews, connect IaC to real DevOps practices: Git, pull requests, pipeline deployment, approvals, and repeatable environments.
