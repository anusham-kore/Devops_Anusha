# Azure DevOps

Azure DevOps provides tools for source control, CI/CD pipelines, artifacts, work tracking, and deployment automation. For interviews, focus on pipeline stages, agents, service connections, variables, approvals, and deployment strategies.

## 1. Azure Repos

Azure Repos hosts Git repositories.

### Used for
- Source code
- Branching
- Pull requests
- Code reviews
- Version history

## 2. Azure Pipelines

Azure Pipelines automates build, test, and deployment.

### Pipeline types
- YAML pipelines
- Classic build and release pipelines

### Interview point
- YAML pipelines are version-controlled with the application code.

## 3. Build Pipeline vs Release Pipeline

### Build pipeline
- Restores dependencies
- Compiles code
- Runs tests
- Publishes artifacts

### Release pipeline
- Deploys artifacts
- Uses approvals and gates
- Promotes releases across environments

## 4. YAML Pipelines

YAML pipelines define CI/CD as code.

### Common sections
- Trigger
- Pool
- Variables
- Stages
- Jobs
- Steps
- Tasks

## 5. Agents

Agents run pipeline jobs.

### Microsoft-hosted agents
- Managed by Microsoft
- Clean environment for each run
- Easy to start

### Self-hosted agents
- Managed by your team
- Useful for private networks or custom tools
- Require maintenance

## 6. Variable Groups

Variable groups store shared variables for pipelines.

### Used for
- Environment names
- App settings
- Non-secret configuration
- Secret references from Key Vault

## 7. Service Connections

Service connections allow Azure DevOps to connect to external services such as Azure subscriptions.

### Interview point
- Service connections are commonly backed by service principals or workload identity federation.

## 8. Artifacts

Artifacts are build outputs used by later stages.

### Examples
- Zip packages
- Docker images
- NuGet packages
- Build files

## 9. Deployment Strategies

### Common strategies
- Rolling deployment
- Blue-green deployment
- Canary deployment
- Manual approval before production
- Rollback to previous artifact

## Hands-On Practice

Use a simple repository and non-production Azure subscription.

### 1. Create a Project

Steps:
1. Open Azure DevOps
2. Create an organization if needed
3. Create a project named `ado-practice`
4. Choose Git for source control

### 2. Create a Repository

Steps:
1. Open `Repos`
2. Create or import a simple application repository
3. Add a basic `README.md`
4. Commit changes

### 3. Create a YAML Pipeline

Steps:
1. Open `Pipelines`
2. Select `New pipeline`
3. Choose Azure Repos Git
4. Select your repository
5. Choose starter pipeline
6. Save and run

Example:

```yaml
trigger:
- main

pool:
  vmImage: ubuntu-latest

steps:
- script: echo "Build started"
  displayName: Build
```

### What to observe
- Pipeline runs on an agent
- YAML file is stored in the repository
- Every run has logs

### 4. Create a Service Connection

Steps:
1. Open Project Settings
2. Select `Service connections`
3. Create an Azure Resource Manager service connection
4. Select subscription and resource group scope where possible
5. Save

### What to observe
- Pipelines need identity and permission to deploy to Azure
- Scope should follow least privilege

### 5. Add an Environment Approval

Steps:
1. Open `Pipelines`
2. Select `Environments`
3. Create environment: `prod`
4. Add approval check
5. Use the environment in a deployment stage

### 6. Clean Up

Steps:
1. Delete test pipelines if no longer needed
2. Remove unused service connections
3. Remove test project if created only for practice

## Common Interview Questions

- What is CI/CD?
  Answer:
  CI builds and tests code automatically. CD deploys validated artifacts to environments automatically or with approvals.

- What is a service connection?
  Answer:
  A service connection lets Azure DevOps authenticate to Azure or another external service.

- What is the difference between Microsoft-hosted and self-hosted agents?
  Answer:
  Microsoft-hosted agents are managed by Microsoft. Self-hosted agents are managed by your team and are useful for private networks or custom tools.

## Final Tip

When explaining pipelines, use this flow: trigger, build, test, publish artifact, deploy to dev, approval, deploy to production, monitor, rollback if needed.
