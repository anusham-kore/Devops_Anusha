# Azure Fundamentals

This file covers the first Azure-specific concepts you should know for interviews. These topics help you understand how Azure is organized, how resources are deployed, and how Microsoft and customers share responsibility for security and operations.

## 1. What Is Azure

Azure is Microsoft's cloud computing platform.

### What Azure provides
- Compute services to run applications and servers
- Storage services to store files, data, and backups
- Networking services to connect resources securely
- Database services for structured and unstructured data
- Security, monitoring, automation, and DevOps services

### Why Azure is used
- Reduces the need to manage physical datacenters
- Helps teams scale resources quickly
- Provides high availability options
- Supports pay-as-you-go pricing
- Offers managed services that reduce operational effort

### Interview point
- Azure is not only virtual machines
- It is a complete cloud platform for infrastructure, applications, data, security, monitoring, and DevOps

## 2. Regions

An Azure region is a geographic area where Microsoft has datacenters.

### Examples
- East US
- West Europe
- Central India
- Southeast Asia

### Why regions matter
- Resources are deployed into specific regions
- Region choice affects latency, availability, compliance, and cost
- Users usually get better performance when resources are closer to them

### Interview point
- A region is the location where Azure resources physically run

## 3. Region Pairs

Azure regions are often paired with another region in the same geography.

### Why region pairs exist
- Help with disaster recovery planning
- Support platform updates with reduced risk
- Keep data within the same geographic boundary where possible

### Interview point
- Region pairs are useful for business continuity and disaster recovery design

## 4. Availability Zones

Availability zones are physically separate datacenter locations inside an Azure region.

### What zones provide
- Independent power
- Independent cooling
- Independent networking

### Why zones matter
- They protect applications from datacenter-level failures
- Zone-redundant services can continue running if one zone has an issue

### Region vs Availability Zone
- Region:
  A geographic area
- Availability zone:
  A separate datacenter location inside a supported region

### Interview point
- Availability zones improve high availability within a region

## 5. Resource Groups

A resource group is a logical container for Azure resources.

### What resource groups contain
- Virtual machines
- Storage accounts
- Virtual networks
- App services
- Databases
- Monitoring resources

### Why resource groups are used
- Organize related resources together
- Apply role-based access control at a group level
- Track costs by project, environment, or application
- Manage lifecycle of related resources together

### Interview point
- A resource group is used for logical organization and management, not for network isolation

## 6. Subscriptions

An Azure subscription is a billing and access boundary.

### What subscriptions are used for
- Billing and cost tracking
- Access control
- Resource limits and quotas
- Separating environments or business units

### Interview point
- A subscription is higher than a resource group in the Azure hierarchy

## 7. Management Groups

Management groups help organize multiple subscriptions.

### Why management groups are used
- Apply governance across many subscriptions
- Assign policies at a higher level
- Organize subscriptions by department, environment, or business unit

### Interview point
- Management groups are useful in large organizations with many subscriptions

## 8. Azure Portal, CLI, and PowerShell

Azure resources can be managed using different tools.

### Azure portal
- Browser-based graphical interface
- Good for learning, visibility, and manual management

### Azure CLI
- Command-line tool
- Works well in Bash, terminals, and automation scripts
- Commands usually start with `az`

### Azure PowerShell
- PowerShell module for Azure management
- Common in Windows and enterprise automation environments
- Commands usually use `Verb-AzNoun` format

## 9. ARM Basics

ARM stands for Azure Resource Manager.

### What ARM does
- Provides the management layer for Azure
- Handles create, update, and delete operations for resources
- Supports templates for Infrastructure as Code
- Applies RBAC, policies, tags, and locks

### Interview point
- ARM is the deployment and management service for Azure resources

## 10. Shared Responsibility Model

The shared responsibility model explains what Microsoft manages and what the customer manages.

### Microsoft is responsible for
- Physical datacenters
- Physical servers
- Physical network
- Cloud platform availability

### Customer is responsible for
- Data
- Identity and access
- Application configuration
- Network security rules
- Operating system patching in some service models

### Responsibility changes by service type
- IaaS:
  Customer manages more, such as OS patching and VM configuration
- PaaS:
  Microsoft manages more platform components
- SaaS:
  Microsoft manages most of the application platform, while customer manages users, data, and access

## Hands-On Practice

Use this practice to become comfortable with the Azure portal, resource groups, regions, storage accounts, and cost visibility.

### 1. Explore the Azure Portal

Go to:

```text
https://portal.azure.com
```

Check these areas:
- Search bar at the top
- Subscriptions
- Resource groups
- All resources
- Cost Management

### 2. Create a Resource Group

Steps:
1. Search for `Resource groups`
2. Select `Create`
3. Select your subscription
4. Enter resource group name: `rg-practice-dev`
5. Select a nearby region, such as `Central India`
6. Select `Review + create`
7. Select `Create`

### What to observe
- A resource group is only a logical container
- It does not create compute or storage by itself
- The region selected for a resource group stores metadata for that resource group

### 3. Create a Storage Account

Steps:
1. Search for `Storage accounts`
2. Select `Create`
3. Select resource group: `rg-practice-dev`
4. Enter a unique lowercase storage account name
5. Select the same region as your resource group
6. Performance: `Standard`
7. Redundancy: `Locally-redundant storage (LRS)`
8. Select `Review + create`
9. Select `Create`

### 4. Create a Blob Container and Upload a File

Steps:
1. Open the storage account
2. Go to `Data storage`
3. Select `Containers`
4. Select `+ Container`
5. Name: `demo`
6. Public access level: `Private`
7. Create the container
8. Open the container
9. Upload a small text file

### 5. Check Cost Management

Steps:
1. Search for `Cost Management`
2. Open your subscription cost view
3. Check actual cost and forecast
4. Review cost by resource group if available

### 6. Clean Up Resources

Steps:
1. Search for `Resource groups`
2. Open `rg-practice-dev`
3. Select `Delete resource group`
4. Type the resource group name to confirm
5. Delete it

## Common Interview Questions

- What is Azure?
  Answer:
  Azure is Microsoft's cloud computing platform. It provides services for compute, storage, networking, databases, security, monitoring, DevOps, and application hosting.

- What is the difference between a region and an availability zone?
  Answer:
  A region is a geographic Azure location. An availability zone is a physically separate datacenter location within a supported region. Zones help protect applications from datacenter-level failures.

- What is a resource group?
  Answer:
  A resource group is a logical container used to organize and manage related Azure resources. It can also be used for access control, cost tracking, and lifecycle management.

- What is the shared responsibility model?
  Answer:
  The shared responsibility model explains which security and operational responsibilities belong to Microsoft and which belong to the customer.

## Final Tip

Practice explaining the hierarchy clearly: management groups contain subscriptions, subscriptions contain resource groups, and resource groups contain resources.
