# DevOps Basics

This file covers the DevOps basics that are important before moving deeper into Azure DevOps, CI/CD pipelines, Infrastructure as Code, and production support scenarios. These topics help you understand how teams build, test, deploy, and operate software in a faster and more reliable way.

## 1. What DevOps Means

DevOps is a way of working that brings development and operations teams together.

### Core idea
- Developers build and change applications
- Operations teams manage deployment, infrastructure, monitoring, and reliability
- DevOps encourages collaboration, automation, faster delivery, and shared ownership

### Why DevOps matters
- Releases become faster and more repeatable
- Manual errors are reduced
- Teams detect issues earlier
- Applications become easier to support in production

### Interview point
- DevOps is not just a toolset
- It is a culture plus practices supported by automation

## 2. CI/CD Concepts

CI/CD is one of the most common DevOps interview topics.

### CI
- CI stands for Continuous Integration
- Developers frequently merge code into a shared repository
- Automated builds and tests run after changes
- The goal is to catch issues early

### CD
- CD can mean Continuous Delivery or Continuous Deployment
- Continuous Delivery means code is always ready to release, but approval may still happen before production
- Continuous Deployment means changes are automatically deployed when checks pass

### Why CI/CD matters
- It speeds up delivery
- It improves software quality
- It reduces the risk of large manual releases

## 3. Version Control with Git

Git is the most common version control system used in DevOps workflows.

### What Git does
- Tracks code changes over time
- Helps multiple people work on the same project
- Supports branching and merging
- Provides history and rollback capability

### Common Git concepts
- `clone` downloads a repository
- `commit` saves changes to history
- `push` sends changes to a remote repository
- `pull` gets the latest changes
- `branch` creates isolated lines of work
- `merge` combines changes

### Why it matters
- Almost every CI/CD pipeline starts with source code stored in Git
- Interviewers often ask about branching and collaboration workflows

## 4. Build and Release Pipelines

Pipelines automate the steps required to turn source code into a deployed application.

### Build pipeline
- Compiles code if needed
- Restores dependencies
- Runs tests
- Creates a deployable package or artifact

### Release pipeline
- Takes the built artifact 
- Deploys it to one or more environments
- May include approvals, checks, and rollback plans

### Common stages
- Source
- Build
- Test
- Package
- Deploy
- Verify

### Why pipelines matter
- They reduce manual deployment work
- They make releases more consistent
- They create traceability for what changed and when

## 5. Infrastructure as Code Basics

Infrastructure as Code means managing infrastructure using code files instead of manual portal clicks.

### What it includes
- Virtual machines
- Networks
- Storage accounts
- App services
- Policies and configuration

### Common benefits
- Repeatable deployments
- Easier version control
- Better consistency across environments
- Faster environment setup

### Common tools
- ARM templates
- Bicep
- Terraform

### Interview point
- IaC helps teams treat infrastructure like application code, with review, versioning, and automation

## 6. Monitoring and Alerting Basics

Monitoring helps teams understand system health and detect problems early.

### Monitoring includes
- CPU, memory, disk, and network metrics
- Application logs
- Availability checks
- Error tracking
- Performance trends

### Alerting includes
- Sending notifications when thresholds are crossed
- Informing teams about failures or unusual behavior
- Triggering actions such as emails, tickets, or automation

### Why this matters
- Deployment is not the end of the job
- Teams must also observe and support systems in production

## 7. DevOps Lifecycle Overview

DevOps is often explained as a lifecycle rather than one single action.

### Typical lifecycle stages
1. Plan
2. Develop
3. Build
4. Test
5. Release
6. Deploy
7. Operate
8. Monitor

### Key idea
- Feedback from monitoring and operations should improve the next development cycle

## 8. Common Deployment Strategies

Deployment strategy is a common scenario topic in interviews.

### Basic deployment
- Replace the old version with the new one
- Simple, but higher risk if something fails

### Blue-green deployment
- Keep two environments
- One serves live traffic and the other receives the new version
- Traffic switches after validation

### Canary deployment
- Release the new version to a small group first
- Watch for errors before wider rollout

### Rollback strategy
- Return to the last stable version if the new deployment fails

### Why this matters
- Good deployment strategy reduces downtime and production risk

## 9. Common DevOps Metrics and Goals

Teams often use simple metrics to measure delivery and reliability.

### Common goals
- Faster release cycles
- Lower change failure rate
- Faster recovery from incidents
- Better deployment consistency

### Interview point
- DevOps is about improving both speed and stability, not just releasing faster

## 10. Common DevOps Mistakes

Interviewers may test your practical thinking through mistakes and scenarios.

### Common mistakes
- Deploying manually without documentation
- Skipping testing before release
- Storing secrets directly in code
- Not monitoring production after deployment
- Making infrastructure changes only through the portal
- Having no rollback plan

### Why this matters
- DevOps maturity is not only about automation
- It also requires safety, visibility, and process discipline

## Common Interview Questions

- What is DevOps?
  Answer:
  DevOps is a culture and set of practices that improve collaboration between development and operations teams. Its goal is to deliver software faster, more reliably, and with more automation and shared ownership.

- What is the difference between CI and CD?
  Answer:
  Continuous Integration focuses on frequently merging code and validating it with automated builds and tests. Continuous Delivery or Continuous Deployment focuses on making validated changes ready for release or automatically deploying them.

- Why is Git important in DevOps?
  Answer:
  Git is important because it tracks code changes, supports collaboration, enables branching and merging, and provides a reliable source for automation pipelines. It also makes reviews and rollback easier.

- What is a pipeline?
  Answer:
  A pipeline is an automated sequence of steps that takes source code through build, test, package, and deployment stages. It reduces manual effort and improves consistency.

- What is Infrastructure as Code?
  Answer:
  Infrastructure as Code is the practice of defining and deploying infrastructure through code files instead of manual configuration. This makes environments repeatable, version-controlled, and easier to automate.

- Why is monitoring important in DevOps?
  Answer:
  Monitoring is important because teams need visibility into application and infrastructure health after deployment. Without monitoring, teams may not detect failures, performance issues, or unusual behavior quickly.

- What is the difference between blue-green and canary deployment?
  Answer:
  Blue-green deployment switches traffic between two full environments, while canary deployment releases the new version to a small subset of users first. Both reduce risk, but they do so in different ways.

- Why is rollback planning important?
  Answer:
  Rollback planning is important because deployments can fail even after testing. A rollback plan helps restore service quickly and reduce business impact.

- What are common DevOps mistakes?
  Answer:
  Common mistakes include manual deployments, lack of testing, poor secret handling, missing monitoring, and not having a rollback strategy. These gaps increase operational risk and reduce reliability.

## Final Tip

Do not study DevOps only as definitions like CI, CD, and IaC. Practice explaining the full flow of how code moves from a developer machine to production, how it is monitored, and how failures are handled.

That practical story-based understanding helps a lot in interviews.
