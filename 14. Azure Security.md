# Azure Security

Azure security covers identity protection, data protection, network security, threat detection, secrets, and compliance. For interviews, focus on defense in depth and least privilege.

## 1. Microsoft Defender for Cloud

Microsoft Defender for Cloud provides cloud security posture management and workload protection.

### Helps with
- Secure score
- Security recommendations
- Regulatory compliance view
- Threat protection
- Defender plans for workloads

### Interview point
- Defender for Cloud helps identify and improve security posture across Azure resources.

## 2. Azure Key Vault

Azure Key Vault stores and manages secrets, keys, and certificates.

### Used for
- Passwords
- API keys
- Certificates
- Encryption keys
- Connection strings

### Interview point
- Applications should read secrets from Key Vault using managed identity where possible.

## 3. Disk Encryption

Azure provides encryption for disks and storage.

### Important ideas
- Platform-managed keys
- Customer-managed keys
- Encryption at rest
- Disk encryption sets

## 4. Network Security Controls

### Common controls
- NSGs
- Azure Firewall
- Web Application Firewall
- Private Endpoint
- DDoS Protection
- Just-in-time VM access

## 5. Identity Security

### Best practices
- Enable MFA
- Use least privilege
- Assign access to groups
- Use managed identities
- Avoid permanent admin access
- Review access regularly

## 6. Secure Score

Secure score measures security posture and provides improvement recommendations.

### Interview point
- Secure score is a guide, not a final guarantee that everything is secure.

## 7. Governance and Compliance

### Tools
- Azure Policy
- Resource locks
- Tags
- Defender for Cloud regulatory compliance
- Activity logs

## Hands-On Practice

Use existing practice resources.

### 1. Create a Key Vault

Steps:
1. Search for `Key vaults`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. Name: unique key vault name
5. Region: same as practice resources
6. Choose standard pricing
7. Create the vault

### What to observe
- Key Vault name must be globally unique
- Access model controls who can read secrets

### 2. Add a Secret

Steps:
1. Open the Key Vault
2. Select `Secrets`
3. Select `Generate/Import`
4. Name: `demo-secret`
5. Value: use a harmless test value
6. Create

### What to observe
- Secret values are hidden after creation
- Access must be granted carefully

### 3. Grant Access to a Managed Identity

Steps:
1. Enable managed identity on a VM or App Service
2. Open Key Vault
3. Go to access control or access policies, depending on vault configuration
4. Grant secret read permission to the managed identity

### What to observe
- The application identity can access the secret without storing credentials
- This is safer than putting passwords in code

### 4. Review Defender for Cloud

Steps:
1. Search for `Microsoft Defender for Cloud`
2. Open `Recommendations`
3. Review secure score
4. Review recommendations for your resources

### What to observe
- Recommendations show security gaps
- Some recommendations require paid Defender plans

### 5. Clean Up

Steps:
1. Delete test secrets
2. Remove role assignments if created only for practice
3. Delete the Key Vault if no longer needed

## Common Interview Questions

- What is Azure Key Vault?
  Answer:
  Azure Key Vault stores and manages secrets, keys, and certificates securely.

- What is Microsoft Defender for Cloud?
  Answer:
  It helps assess and improve cloud security posture and provides workload protection recommendations and alerts.

- How should an application access secrets in Azure?
  Answer:
  Prefer managed identity with Key Vault access instead of storing secrets in code, config files, or pipelines.

## Final Tip

Security answers should include identity, network, data, monitoring, and governance controls together.
