# Azure Compute Services

Azure compute services run applications, servers, containers, background jobs, and serverless workloads. For interviews, focus on when to choose each service and how availability, scaling, cost, and management responsibility change.

## 1. Virtual Machines

Azure Virtual Machines provide Infrastructure as a Service.

### What VMs are used for
- Running Windows or Linux servers
- Hosting legacy applications
- Running custom software that needs OS-level control
- Lift-and-shift migrations from on-premises

### What you manage
- Operating system updates
- Installed software
- VM security configuration
- Disk management
- Backup and monitoring configuration

### Interview point
- Choose VMs when you need full control of the operating system

## 2. VM Sizes and Pricing Basics

VM size controls CPU, memory, temporary disk, and network performance.

### Pricing factors
- VM size
- Region
- Operating system
- Running hours
- Disk type and size
- Public IP and bandwidth usage

### Cost tip
- Stop and deallocate practice VMs when not in use
- Stopped but not deallocated VMs can still reserve compute capacity

## 3. Availability Sets and Availability Zones

### Availability set
- Protects VMs from planned maintenance and some hardware failures inside a datacenter
- Uses fault domains and update domains

### Availability zone
- Places resources in separate datacenter locations inside a supported region
- Provides stronger protection than an availability set

### Interview point
- Availability sets protect across racks inside a datacenter
- Availability zones protect across separate datacenter locations inside a region

## 4. Virtual Machine Scale Sets

VM Scale Sets deploy and manage a group of identical VMs.

### Used for
- Auto-scaling web servers
- Batch processing
- Stateless application tiers
- Handling traffic spikes

### Interview point
- Scale sets are useful when many identical VMs need to scale automatically

## 5. Azure App Service

App Service is a Platform as a Service option for hosting web apps and APIs.

### Supports
- .NET
- Java
- Node.js
- Python
- PHP
- Containers

### Why use App Service
- No server management
- Built-in scaling
- Deployment slots
- Easy custom domain and TLS setup
- Integration with CI/CD

### Interview point
- Choose App Service when you need to host a web application without managing the VM OS

## 6. Azure Functions

Azure Functions is a serverless compute service.

### Common triggers
- HTTP request
- Timer schedule
- Queue message
- Blob upload
- Event Grid event

### Use cases
- Small automation tasks
- Event-driven processing
- Scheduled cleanup jobs
- Lightweight APIs

### Interview point
- Choose Functions for event-driven code where you do not want to manage infrastructure

## 7. Azure Container Instances

Azure Container Instances runs containers without managing servers or Kubernetes.

### Used for
- Short-running container jobs
- Testing containers
- Simple isolated workloads

### Interview point
- ACI is good for simple containers, but not for complex orchestration

## 8. Azure Kubernetes Service

AKS is Azure's managed Kubernetes service.

### Used for
- Microservices
- Container orchestration
- Rolling deployments
- Autoscaling container workloads
- Production container platforms

### What Azure manages
- Kubernetes control plane
- Control plane availability
- Some platform operations

### What you manage
- Worker nodes
- Pods, deployments, services, ingress
- Container images
- Cluster networking and security configuration

### Interview point
- Choose AKS when the application needs Kubernetes orchestration features

## 9. Choosing the Right Compute Service

| Requirement | Good Choice |
| --- | --- |
| Need full OS control | Virtual Machine |
| Need many identical VMs | VM Scale Set |
| Web app without OS management | App Service |
| Event-driven small code | Azure Functions |
| Simple container run | Container Instances |
| Complex container platform | AKS |

## Hands-On Practice

Use a low-cost region and delete resources after practice.

### 1. Create a Linux Virtual Machine

Steps:
1. Search for `Virtual machines`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. VM name: `vm-dev-01`
5. Region: same as your resource group
6. Image: Ubuntu LTS
7. Size: choose a small low-cost size
8. Authentication: SSH key or password for practice
9. Inbound ports: allow SSH only if needed
10. Select `Review + create`
11. Create the VM

### What to observe
- VM creation also creates related resources such as NIC, disk, public IP, and NSG
- VM cost depends on compute, disks, and networking

### 2. Connect to the VM

Command:

```bash
ssh <username>@<public-ip>
```

Check basic system details:

```bash
hostname
df -h
free -m
```

### What to observe
- You are responsible for OS-level management inside the VM
- NSG rules control whether SSH is reachable

### 3. Create an App Service

Steps:
1. Search for `App Services`
2. Select `Create`
3. Choose resource group `rg-practice-dev`
4. Name: `app-practice-dev`
5. Runtime stack: choose any familiar runtime
6. Region: same region
7. Pricing plan: choose a free or low-cost plan if available
8. Create the app

### What to observe
- You get a web app URL without creating a VM
- Scaling and deployment options are available from the App Service blade

### 4. Create a Basic Function App

Steps:
1. Search for `Function App`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. Function app name: unique name
5. Runtime stack: choose one runtime
6. Hosting: choose a low-cost option suitable for practice
7. Create the function app

### What to observe
- Function Apps are built for trigger-based execution
- Some hosting plans require a storage account

### 5. Clean Up

Steps:
1. Stop and deallocate the VM if you want to keep it temporarily
2. Delete the full practice resource group when finished
3. Confirm disks, public IPs, and App Service plans are deleted

## Common Interview Questions

- When would you choose App Service over a VM?
  Answer:
  Choose App Service when hosting a web app or API and you do not need OS-level control. Azure manages the platform, patching, and web hosting environment.

- What is a VM Scale Set?
  Answer:
  A VM Scale Set manages a group of identical VMs and can scale them automatically based on demand.

- What is the difference between Azure Functions and App Service?
  Answer:
  App Service hosts long-running web apps and APIs. Azure Functions runs event-driven code triggered by events such as HTTP requests, timers, queues, or file uploads.

- When would you choose AKS?
  Answer:
  Choose AKS when applications are containerized and need Kubernetes features such as orchestration, service discovery, rolling deployments, autoscaling, and ingress management.

## Final Tip

In interviews, answer compute questions by starting with the workload requirement: full OS control, web hosting, event-driven execution, simple containers, or Kubernetes orchestration.
