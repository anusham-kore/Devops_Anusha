# Logs and Troubleshooting

This topic is critical for real-world Linux work. Interviewers often ask troubleshooting scenarios to check how you think under pressure.

## 1. System Log Locations

### Common locations

`/var/log/messages`
`/var/log/secure`
`/var/log/syslog`
`/var/log/dmesg`
`/var/log/cron`

## 2. Application Log Analysis

### Useful commands

```bash
tail -f /var/log/messages
grep -i error app.log
less app.log
awk '/ERROR/ {print}' app.log
```

## 3. `journalctl` Usage

### Useful commands

```bash
journalctl -u nginx
journalctl -b
journalctl -p err
journalctl --since today
```

## 4. Boot Issue Basics

### Useful commands

```bash
journalctl -b
dmesg | less
systemctl --failed
```

## 5. High CPU Troubleshooting

### Useful commands

```bash
top
ps -eo pid,%cpu,%mem,cmd --sort=-%cpu | head
pidstat 1 5
```

## 6. High Memory Troubleshooting

### Useful commands

```bash
free -h
top
ps -eo pid,%mem,cmd --sort=-%mem | head
vmstat 1 5
```

## 7. Disk Full Troubleshooting

### Useful commands

```bash
df -h
du -sh /var/*
df -i
find / -xdev -type f -size +500M 2>/dev/null
```

## 8. Service Failure Troubleshooting

### Useful commands

```bash
systemctl status nginx
journalctl -u nginx
ss -lntp
```

## 9. Network Issue Debugging

### Useful commands

```bash
ip a
ip route
ping
curl
ss -tulpn
```

##  Real Interview Scenarios

Scenario 1:
Server is slow.

Check CPU, memory, disk, IO, and logs in this order.

Scenario 2:
Service is down after reboot.

Check:

```bash
systemctl status service_name
journalctl -b
journalctl -u service_name
```

Scenario 3:
Disk is full unexpectedly.

Check for logs, large files, old backups, and inode exhaustion.

## Summary

Strong Linux troubleshooting means starting from symptoms, checking logs, validating resources, and isolating the exact failing layer.
