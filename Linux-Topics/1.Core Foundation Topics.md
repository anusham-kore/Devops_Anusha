# Core Foundation Topics

This topic builds the base for Linux administration interviews. For a 4-year experience profile, interviewers usually expect not only definitions, but also practical usage, troubleshooting approach, and command-level confidence.

## 1. Linux Architecture Basics

### What it means

Linux architecture mainly consists of:

Hardware
Kernel
Shell
System utilities
Applications

### Simple understanding

Hardware is the physical machine.
Kernel is the core of the operating system.
Shell is the interface used to interact with the system.
Utilities and applications run on top of the operating system.

### Interview point

Linux uses a layered architecture where the kernel manages hardware resources and the shell provides user interaction.

### Important commands

```bash
uname -a
hostnamectl
arch
lscpu
lsblk
cat /etc/os-release
```

### Scenario

If an interviewer asks how to identify the OS and system architecture of a server, you can say:

Use `cat /etc/os-release` to check OS details, `uname -a` for kernel information, and `arch` or `lscpu` to identify CPU architecture.

### Common interview questions

What is the role of the kernel in Linux?
What is the difference between shell and kernel?
How do you identify Linux OS version and architecture?

## 2. Boot Process Overview

### Boot flow

BIOS or UEFI
Bootloader such as GRUB
Kernel loading
`initramfs`
`systemd` or init process
Target or runlevel services

### Simple understanding

When the system powers on, firmware starts the bootloader. The bootloader loads the kernel. The kernel initializes hardware and starts the first user-space process, usually `systemd`.

### Important commands

```bash
systemctl get-default
systemctl list-units --type=target
journalctl -b
dmesg | tail
who -b
uptime
```

### Scenario

If the server rebooted unexpectedly and you need to inspect boot logs, use `journalctl -b` for current boot logs and `who -b` to verify the last boot time.

### Common interview questions

Explain Linux boot process.
What is GRUB?
What is the role of `systemd` during boot?

## 3. Kernel and Shell Basics

### Kernel

The kernel manages:

CPU scheduling
Memory management
Device drivers
File systems
Process control

### Shell

The shell interprets user commands and sends requests to the kernel.

Examples:

Bash
Sh
Ksh
Zsh

### Important commands

```bash
uname -r
echo $SHELL
ps -p $$
which bash
cat /proc/version
```

### Scenario

If a script behaves differently for different users, check which shell they are using with `echo $SHELL` and review their profile files.

### Common interview questions

What is the difference between kernel space and user space?
What is a shell?
How do you check the current shell?

## 4. File System Hierarchy Standard

### Important directories

`/`
root of the filesystem

`/bin`
essential user commands

`/sbin`
system administration commands

`/etc`
configuration files

`/home`
user home directories

`/var`
variable data like logs and spool

`/tmp`
temporary files

`/usr`
user applications and libraries

`/opt`
optional software

`/dev`
device files

`/proc`
process and kernel information

`/boot`
boot-related files

### Important commands

```bash
pwd
ls /
cd /etc
du -sh /var
ls -ld /tmp
```

### Scenario

If logs are filling the disk, likely locations include `/var/log`. If user login issues are reported, check configuration under `/etc`.

### Common interview questions

What is stored in `/etc`?
What is `/proc`?
Why is `/var` important?

## 5. Users, Groups, and Permissions

### Basic concepts

Every file and process is associated with:

Owner
Group
Permissions

Permission types:

Read
Write
Execute

Permission groups:

User
Group
Others

### Numeric permission values

`4` = read
`2` = write
`1` = execute

Example:

`755` means owner has full access, group and others have read and execute.

### Important files

`/etc/passwd`
`/etc/shadow`
`/etc/group`

### Important commands

```bash
id
who
whoami
groups
ls -l
chmod 755 file.txt
chown user:group file.txt
stat file.txt
```

### Scenario

An application cannot read a config file. First check ownership and permission using `ls -l` and `stat`. Then fix with `chown` or `chmod` as needed.

### Common interview questions

What is the difference between `/etc/passwd` and `/etc/shadow`?
Explain `755`, `644`, and `777`.
How do you change file ownership?

## 6. Process and Job Control

### Process basics

A process is a running instance of a program.

Important concepts:

PID
PPID
foreground process
background process
zombie process
daemon process

### Job control

Foreground job runs in the current shell.
Background job runs behind the shell.

### Important commands

```bash
ps -ef
top
jobs
bg
fg
nohup sleep 300 &
kill -9 <pid>
pgrep sshd
```

### Scenario

You started a long-running script and want it to continue after logout. Use `nohup command &` and verify with `ps -ef`.

### Common interview questions

What is the difference between a process and a job?
What is a zombie process?
How do you run a process in background?

## 7. Package Management

### Why it matters

Package managers install, update, and remove software while managing dependencies.

### Common package tools

RHEL/CentOS:
`yum`, `dnf`, `rpm`

Ubuntu/Debian:
`apt`, `dpkg`

### Important commands

```bash
rpm -qa | head
yum install nginx -y
dnf update -y
apt update
apt install nginx -y
dpkg -l | head
which nginx
```

### Scenario

If a package installation fails because of missing dependencies, check repository configuration and package manager output, then retry after metadata refresh like `apt update` or `yum makecache`.

### Common interview questions

What is the difference between `rpm` and `yum`?
What is the difference between `dpkg` and `apt`?
How do you verify whether a package is installed?

## 8. Editors Like vi or vim

### Why this matters

Linux admins often need to edit configs directly on servers.

### Basic modes in `vi` or `vim`

Command mode
Insert mode
Last-line mode

### Basic operations

Press `i` to enter insert mode
Press `Esc` to return to command mode
Use `:w` to save
Use `:q` to quit
Use `:wq` to save and quit
Use `:q!` to quit without saving

### Useful commands

```bash
vim /etc/hosts
vi /etc/fstab
```

### Scenario

If you need to urgently update a server config during a production issue, `vi` is usually the fastest editor available.

### Common interview questions

How do you save and quit in `vi`?
How do you quit without saving?
Why is `vi` important for Linux admins?

Shell scripting is used to automate repetitive tasks in Linux.

### Common concepts

Variables
Conditions
Loops
Functions
Exit codes

 Real Interview Scenarios

Scenario 1:
You cannot execute a script.

Check:
file permissions with `ls -l`
shebang line in the script
interpreter availability
execute permission using `chmod +x`

Scenario 2:
A user cannot run a command that others can run.

Check:
user permissions
group membership
`PATH` variable
shell profile settings

Scenario 3:
The system rebooted and a service did not come back.

Check:
last boot time using `who -b`
boot logs using `journalctl -b`
default target using `systemctl get-default`
service status using `systemctl status <service>`

Scenario 4:
An application cannot update its own file.

Check:
owner and group using `ls -l`
current user with `whoami`
directory permissions
mount status if filesystem is read-only
