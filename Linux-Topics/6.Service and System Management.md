# Service and System Management

This topic covers how Linux manages services, system startup, logs, scheduled jobs, and system state. It is heavily used in production support and DevOps work.

## 1. `systemctl`

### Useful commands

```bash
systemctl status nginx
systemctl start nginx
systemctl stop nginx
systemctl restart nginx
systemctl enable nginx
systemctl disable nginx
systemctl is-enabled nginx
```

## 2. `journalctl`

### Useful commands

```bash
journalctl -u nginx
journalctl -xe
journalctl -b
journalctl --since "1 hour ago"
```

## 3. `service` Command Basics

### Useful commands

```bash
service nginx status
service nginx restart
```

## 4. System Targets and Runlevels

### Useful commands

```bash
systemctl get-default
systemctl set-default multi-user.target
systemctl list-units --type=target
runlevel
```

## 5. Startup Services

### Core idea

Important services can be enabled to start automatically during boot.

## 6. Cron Jobs

### Useful commands

```bash
crontab -l
crontab -e
cat /etc/crontab
ls /etc/cron.d
```

## 7. `at` Command

### Useful commands

```bash
at now + 10 minutes
atq
atrm 1
```

## 8. Log Rotation Basics

### Useful paths and commands

```bash
cat /etc/logrotate.conf
ls /etc/logrotate.d
logrotate -d /etc/logrotate.conf
```

##  Real Interview Scenarios

Scenario 1:
Service is not starting.

Check:

```bash
systemctl status service_name
journalctl -u service_name
ss -lntp
```

Scenario 2:
Cron job is not running.

Check:

```bash
crontab -l
grep CRON /var/log/cron
systemctl status crond
```

Scenario 3:
Logs are growing too fast.

Check logrotate configuration and log generation source.

## Summary

Be comfortable with `systemctl`, `journalctl`, cron, runlevels or targets, and service startup troubleshooting.
