# Performance and Monitoring

Performance monitoring helps you identify bottlenecks before they become outages. Interviewers often use performance scenarios to test how systematically you troubleshoot.

## 1. CPU Usage Analysis

### Useful commands

```bash
top
mpstat
sar -u 1 5
ps -eo pid,%cpu,cmd --sort=-%cpu | head
```

## 2. Memory Usage Analysis

### Useful commands

```bash
free -h
vmstat 1 5
sar -r 1 5
ps -eo pid,%mem,cmd --sort=-%mem | head
```

## 3. Disk I/O Basics

### Useful commands

```bash
iostat -x 1 5
iotop
vmstat 1 5
```

## 4. Load Average

### Interview point

Load average shows demand on the system, not just CPU percentage.

### Useful commands

```bash
uptime
cat /proc/loadavg
```

## 5. Monitoring Tools

### Common tools

`top`
`vmstat`
`iostat`
`sar`
`free`
`uptime`

## 6. Basic Capacity Checks

### Useful commands

```bash
df -h
free -h
nproc

```

## 7. Identifying Bottlenecks

### Typical bottleneck areas

CPU
memory
disk I/O
network
application lockups

##  Real Interview Scenarios

Scenario 1:
Server is slow but CPU is low.

Check memory pressure, I/O wait, and load average.

Scenario 2:
Application response time is poor.

Check:

```bash
top
iostat -x 1 5
ss -tulpn
journalctl -u app
```

Scenario 3:
Memory keeps growing over time.

Investigate top memory consumers and whether swap usage is increasing.

## Summary

For interviews, know how to separate CPU, memory, disk, and load issues using standard Linux monitoring commands.
