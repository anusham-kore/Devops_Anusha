# Networking Topics

Networking is one of the most important Linux interview areas. For a 4-year experience profile, you should be able to explain concepts clearly, use basic troubleshooting commands confidently, and handle real-time connectivity scenarios.

## 1. OSI and TCP/IP Basics

### What this topic means

These are networking models used to understand how data travels from one system to another.

### OSI model

The OSI model is a conceptual 7-layer model:

1. Physical
2. Data Link
3. Network
4. Transport
5. Session
6. Presentation
7. Application

It is mainly used for understanding and learning networking.

### TCP/IP model

The TCP/IP model is the practical model used in real networks and Linux systems.

It has 4 layers:

1. Network Access
2. Internet
3. Transport
4. Application

### Difference between OSI and TCP/IP

OSI is a reference model used for learning and explanation.
TCP/IP is the real-world protocol model used on the internet.

### Practical mapping examples

`IP` works at the Network or Internet layer.
`TCP` and `UDP` work at the Transport layer.
`HTTP`, `HTTPS`, `SSH`, and `DNS` work at the Application layer.

### Interview point

If an interviewer asks the difference, a strong answer is:

"OSI is a conceptual 7-layer model used for understanding networking. TCP/IP is the practical protocol stack used in real communication over networks."

## 2. IP Addressing and Subnetting

### What this topic means

IP addressing is used to identify devices in a network. Subnetting is used to divide networks into smaller logical parts.

### IP address

An IP address is the unique address assigned to a device in a network.

Example:

`192.168.1.10`

This helps one device communicate with another.

### Subnet mask

A subnet mask tells which part of the IP address belongs to the network and which part belongs to the host.

Example:

`255.255.255.0`

This means the first part is the network portion and the last part is for hosts in that network.

### Gateway

A gateway is the router or network device used to send traffic outside the local subnet.

If a server wants to reach another network or the internet, it usually sends traffic to the default gateway.

Example:

Server IP: `192.168.1.20`
Gateway: `192.168.1.1`

### CIDR notation

CIDR is the short way to write a subnet mask.

Example:

`192.168.1.10/24`

Here `/24` means 24 bits are used for the network portion.

`/24` is equal to subnet mask `255.255.255.0`

### Why this matters

If IP address, subnet mask, or gateway is incorrect, the server may not be able to communicate with other systems.

### Interview point

You should be able to explain:

What an IP address is
What a subnet mask does
Why a gateway is needed
How CIDR simplifies subnet notation

## 3. Routing Basics

### What this topic means

Routing decides where a packet should go when it leaves a system.

Linux uses a routing table to determine:

Whether the destination is in the same subnet
Whether the packet should go through a gateway
Which interface should be used

### Important commands

```bash
ip route
route -n
traceroute google.com
```

### Example

If your server IP is `192.168.1.20/24` and it needs to reach `8.8.8.8`, the traffic will go to the default gateway because `8.8.8.8` is outside the local subnet.

### Interview point

If a server can communicate locally but not externally, you should check:

default gateway
routing table
interface status

## 4. DNS Basics

### What this topic means

DNS converts domain names into IP addresses.

Humans use names like `google.com`, but systems need IP addresses to communicate.

### Important files and commands

```bash
cat /etc/resolv.conf
nslookup google.com
dig google.com
host google.com
```

### Important file

`/etc/resolv.conf`

This file usually contains DNS server entries used by the system.

### Common scenario

If `ping 8.8.8.8` works but `ping google.com` fails, it usually means network connectivity is fine but DNS resolution has a problem.

### Interview point

Be able to explain:

What DNS does
How to verify DNS resolution
How to identify DNS-related issues

## 5. SSH, SCP, SFTP

### What this topic means

These are secure tools used for remote access and file transfer.

### SSH

Used for secure remote login to another Linux system.

Example:

```bash
ssh user@server
```

### SCP

Used for secure file copy between systems.

Example:

```bash
scp file.txt user@server:/tmp/
```

### SFTP

Used for interactive secure file transfer.

Example:

```bash
sftp user@server
```

### Interview point

`SSH` is mainly for remote login.
`SCP` is for copying files securely.
`SFTP` is for secure interactive file transfer.

### Common scenario

If login works through SSH but file transfer fails, check path, file permissions, remote user access, and firewall/network restrictions.

## 6. Network Troubleshooting Commands

### What this topic means

These commands help identify whether the problem is:

network reachability
DNS
application response
port access
routing

### Important commands

```bash
ping 8.8.8.8
ping google.com
traceroute google.com
netstat -tulpn
ss -tulpn
curl -I http://localhost
telnet host 80
nc -zv host 443
```

### `ping`

Checks whether a host is reachable.

### `traceroute`

Shows the path taken by packets to the destination.

### `netstat`

Older command used to view network connections and listening ports.

### `ss`

Modern replacement for `netstat`.

### `curl`

Used to test HTTP or HTTPS endpoints.

### `telnet`

Can be used to check whether a remote port is reachable.

### `nc`

Also called `netcat`, useful for checking port connectivity.

### Interview point

If a web app is not accessible:

Use `ping` to test basic connectivity
Use `ss` to see whether the service is listening
Use `curl` to test the web response
Use `nc` or `telnet` to test port reachability

## 7. Interface Configuration Basics

### What this topic means

A network interface is the network card or virtual interface used by the system for communication.

Examples:

`eth0`
`ens33`
`ens160`

### Important commands

```bash
ip a
ip addr show
ip link
nmcli device status
ethtool eth0
```

### `ip a`

Shows IP addresses assigned to interfaces.

### `ip link`

Shows whether interfaces are up or down.

### `nmcli`

Used with NetworkManager to view and manage interface configuration.

### `ethtool`

Shows interface link speed, duplex, and driver details.

### Interview point

If the server has no connectivity, first check:

whether the interface is up
whether it has an IP address
whether the cable or link is active

## 8. `/etc/hosts`

### What this topic means

`/etc/hosts` is a local file used to map hostnames to IP addresses.

Example:

```text
192.168.1.50 appserver
```

### Why it matters

It is useful for local testing, temporary name resolution, or when DNS is unavailable.

### Interview point

If one server can resolve a hostname and another cannot, compare:

`/etc/hosts`
DNS settings
name resolution tools like `nslookup`

## 9. Firewall Basics

### What this topic means

A firewall controls which network traffic is allowed or blocked.

In Linux, common firewall tools are:

`iptables`
`firewalld`

### Important commands

```bash
iptables -L -n
firewall-cmd --list-all
firewall-cmd --list-ports
```

### Common scenario

An application is running and listening on port `8080`, but users cannot access it from another machine.

Possible reasons:

service not listening on correct IP
firewall blocking the port
network route issue
wrong security rules

### Interview point

When a port is not reachable, check in order:

Is the application running
Is the port listening
Is the firewall allowing the port
Is the route and network path correct

##  Real Interview Scenarios

### Scenario 1: Server can ping IP but not domain

This usually means:

network is working
DNS resolution is failing

Check:

```bash
cat /etc/resolv.conf
nslookup google.com
dig google.com
```

### Scenario 2: Port is not reachable

Check:

```bash
ss -lntp
nc -zv server 8080
firewall-cmd --list-ports
```

### Scenario 3: SSH is not working

Check:

```bash
systemctl status sshd
ss -lntp | grep ssh
firewall-cmd --list-all
```

### Scenario 4: Hostname works on one server but not another

Check:

```bash
cat /etc/hosts
cat /etc/resolv.conf
nslookup hostname
```

## Summary

For Linux networking interviews, be strong in:

OSI vs TCP/IP understanding
IP, subnet, gateway, and CIDR
routing basics
DNS troubleshooting
SSH and secure file transfer
network troubleshooting commands
interface checks
`/etc/hosts`
firewall basics

If these basics are strong, you can solve many real-world Linux network issues with confidence.
