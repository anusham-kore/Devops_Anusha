# Operating Systems

This file covers the operating system basics that are important before going deeper into Azure administration, troubleshooting, and DevOps work. These topics help you understand how servers behave, how applications run, and how to investigate common production issues.

## 1. Linux Basics

Linux is widely used in cloud environments, web servers, containers, and automation workflows.

### Common Linux Distributions
- Ubuntu
- CentOS
- Red Hat Enterprise Linux
- Debian

### Why Linux matters
- Many cloud workloads run on Linux
- Most container platforms are Linux-based
- Troubleshooting often starts from the command line

### Basic Linux Commands
- `pwd` shows the current directory
- `ls` lists files and folders
- `cd` changes directories
- `cp` copies files
- `mv` moves or renames files
- `rm` removes files
- `cat` displays file content
- `mkdir` creates directories

## 2. Windows Server Basics

Windows Server is commonly used for enterprise applications, Active Directory, IIS, and many internal business systems.

### What Windows Server is used for
- Hosting web applications with IIS
- Running Microsoft enterprise services
- Managing users and policies with Active Directory
- Supporting file sharing and remote administration

### Why it matters
- Many organizations use both Linux and Windows servers
- Azure environments often include Windows-based workloads
- Support and admin roles frequently require Windows troubleshooting

## 3. File System Navigation

You should be comfortable locating files, configuration folders, and logs.

### Linux File System Basics
- `/etc` stores configuration files
- `/var/log` stores logs
- `/home` stores user directories
- `/tmp` stores temporary files
- `/bin` and `/usr/bin` contain commands and binaries

### Windows File System Basics
- `C:\Windows` stores core system files
- `C:\Program Files` stores installed applications
- `C:\Users` stores user profiles
- `C:\Temp` is often used for temporary work

### Why this matters
- Many issues are solved by finding the correct config or log file
- Interviewers may ask where logs or service settings are usually stored

## 4. Process and Service Management

Processes are running programs, and services are background processes that support the operating system or applications.

### Linux Basics
- `ps` shows running processes
- `top` or `htop` shows live resource usage
- `systemctl status <service>` checks a service
- `systemctl start <service>` starts a service
- `systemctl stop <service>` stops a service
- `systemctl restart <service>` restarts a service

### Windows Basics
- Task Manager shows processes and performance
- `services.msc` shows services
- PowerShell can manage services with commands like `Get-Service` and `Restart-Service`

### Why this matters
- If an application is down, a stopped or failed service is often the first thing to check

## 5. User and Group Management

Operating systems use users and groups to control who can log in and what actions they can perform.

### Linux Basics
- `useradd` creates a user
- `passwd` sets or changes a password
- `groupadd` creates a group
- Users can be added to groups for shared permissions

### Windows Basics
- User accounts can be local or domain-based
- Groups are used to assign access to systems and resources
- Administrators have elevated privileges

### Why this matters
- Access problems often come from missing group membership or incorrect user permissions

## 6. Permissions and Access Control

Permissions define who can read, write, or execute files and who can manage resources.

### Linux Permissions
- `r` means read
- `w` means write
- `x` means execute
- Permissions are set for user, group, and others
- `chmod` changes permissions
- `chown` changes file ownership

### Windows Permissions
- NTFS permissions control access to files and folders
- Common rights include read, write, modify, and full control

### Why this matters
- A service may fail not because it is broken, but because it cannot access the file, folder, or port it needs

## 7. Logs and Troubleshooting

Logs are one of the most important sources of information when diagnosing problems.

### Linux Logs
- `/var/log/syslog` or `/var/log/messages` for system activity
- `/var/log/auth.log` for authentication events
- Application logs may be stored in custom directories
- `journalctl` can be used to view systemd logs

### Windows Logs
- Event Viewer is the main tool
- Common categories include Application, Security, and System logs

### Basic Troubleshooting Approach
1. Understand the symptom
2. Check whether the service or process is running
3. Review logs and error messages
4. Validate permissions, network access, and configuration
5. Restart the service if appropriate and verify the result

## Common Interview Questions

- What is the difference between a process and a service?
  Answer:
  A process is any running program, while a service is usually a background process that starts automatically and supports the system or applications. For example, a browser is a process, but a web server like Apache or IIS runs as a service.

- What is the difference between Linux and Windows Server in administration?
  Answer:
  Linux administration is often command-line driven and heavily used in cloud and automation environments, while Windows Server administration commonly uses graphical tools along with PowerShell. Both can be managed from the command line, but their tools and conventions differ.

- Why are file permissions important?
  Answer:
  File permissions protect systems and data by controlling who can read, modify, or execute files. Incorrect permissions can either expose sensitive data or stop an application from working.

- What would you check if an application is down on a server?
  Answer:
  First check whether the process or service is running, then review logs, system resource usage, network reachability, and permissions. This structured approach helps identify whether the issue is with the app, the OS, or connectivity.

- What is the purpose of logs in troubleshooting?
  Answer:
  Logs show what happened, when it happened, and often why it happened. They help you move from guessing to evidence-based troubleshooting.

- What is the role of users and groups?
  Answer:
  Users represent identities, and groups make permission management easier by assigning access to multiple users at once. This simplifies administration and improves security.

- What is the difference between authentication and permissions at the OS level?
  Answer:
  Authentication verifies who the user is, while permissions decide what that user can do after logging in. A person may successfully log in but still be unable to open a protected file or restart a service.

- What would you check if a service fails to start?
  Answer:
  Check the service status, error messages, logs, configuration files, dependencies, and permissions. Also confirm the required port is free and the service account has the access it needs.

## Final Tip

Do not study operating systems only as theory. Practice basic commands, service checks, file permissions, and log reading on both Linux and Windows where possible.

That practical comfort helps a lot in interviews and real troubleshooting.
