# Azure Networking

Azure networking connects resources securely inside Azure, to the internet, and to on-premises environments. For interviews, focus on VNets, subnets, NSGs, routing, private access, load balancing, and troubleshooting.

## 1. Virtual Networks

A virtual network, or VNet, is a private network in Azure.

### What VNets provide
- Private IP address space
- Subnets
- Connectivity between Azure resources
- Control over network traffic
- Integration with VPN, ExpressRoute, and private endpoints

### Interview point
- A VNet is the core networking boundary for Azure resources

## 2. Subnets

Subnets divide a VNet address space into smaller networks.

### Why subnets are used
- Separate application tiers
- Apply NSG rules at subnet level
- Reserve space for special services
- Improve network organization

### Example
- `subnet-web`
- `subnet-app`
- `subnet-db`

## 3. Network Security Groups

NSGs filter inbound and outbound traffic using security rules.

### NSG rules include
- Source
- Destination
- Port
- Protocol
- Direction
- Priority
- Allow or deny action

### Interview point
- NSGs are commonly used to control VM and subnet traffic

## 4. Application Security Groups

Application Security Groups group VMs logically for NSG rules.

### Example
- Create `asg-webservers`
- Add web VMs
- Allow HTTP traffic to that ASG

### Interview point
- ASGs make NSG rules easier to manage when IP addresses change

## 5. Azure Firewall

Azure Firewall is a managed network security service.

### Used for
- Centralized traffic filtering
- Outbound internet control
- Application and network rules
- Threat intelligence-based filtering

### NSG vs Azure Firewall
- NSG:
  Basic subnet or NIC-level traffic filtering
- Azure Firewall:
  Centralized, stateful, managed firewall with advanced controls

## 6. Load Balancer

Azure Load Balancer distributes TCP and UDP traffic.

### Used for
- VM traffic distribution
- High availability for backend VMs
- Layer 4 load balancing

### Interview point
- Azure Load Balancer works at Layer 4

## 7. Application Gateway

Application Gateway is a Layer 7 web traffic load balancer.

### Features
- HTTP and HTTPS routing
- Path-based routing
- SSL termination
- Web Application Firewall option

### Interview point
- Choose Application Gateway for web traffic routing and WAF needs

## 8. VPN Gateway

VPN Gateway connects Azure VNets to on-premises networks over encrypted tunnels.

### Used for
- Site-to-site VPN
- Point-to-site VPN
- VNet-to-VNet VPN

## 9. ExpressRoute

ExpressRoute provides private connectivity between on-premises networks and Azure through a connectivity provider.

### Why use ExpressRoute
- Private connection
- More predictable performance
- Useful for enterprise and hybrid cloud workloads

### Interview point
- ExpressRoute does not use the public internet as the main transport path

## 10. Private Endpoint and Service Endpoint

### Service Endpoint
- Keeps traffic to supported Azure services on the Azure backbone
- The service still uses its public endpoint
- Access can be restricted to selected VNets or subnets

### Private Endpoint
- Gives an Azure service a private IP address inside your VNet
- Allows private access without public exposure

### Interview point
- Private Endpoint is stronger for private access because the service is reached through a private IP

## 11. DNS in Azure

DNS resolves names to IP addresses.

### Azure DNS options
- Azure-provided DNS
- Azure DNS public zones
- Azure Private DNS zones
- Custom DNS servers

### Interview point
- Private endpoints usually require correct private DNS configuration

## 12. VNet Peering

VNet peering connects two VNets privately using the Azure backbone.

### Important points
- Low-latency private connectivity
- VNets must have non-overlapping address spaces
- Peering is not transitive by default

### Interview point
- VNet peering lets resources in different VNets communicate privately

## Hands-On Practice

Use small resources and delete them after practice.

### 1. Create a Virtual Network

Steps:
1. Search for `Virtual networks`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. Name: `vnet-practice-dev`
5. Region: same as your resource group
6. Address space: `10.10.0.0/16`
7. Create subnet `subnet-web` with `10.10.1.0/24`
8. Create the VNet

### What to observe
- A VNet defines private IP address space
- Subnets divide the address space into smaller ranges

### 2. Create a Network Security Group

Steps:
1. Search for `Network security groups`
2. Select `Create`
3. Name: `nsg-web-dev`
4. Region: same region
5. Resource group: `rg-practice-dev`
6. Create

### 3. Associate NSG to a Subnet

Steps:
1. Open `nsg-web-dev`
2. Select `Subnets`
3. Select `Associate`
4. Choose `vnet-practice-dev`
5. Choose `subnet-web`
6. Save

### What to observe
- NSGs can be associated with subnets or network interfaces
- Subnet-level rules apply to resources in that subnet

### 4. Add an Inbound Security Rule

Steps:
1. Open `nsg-web-dev`
2. Select `Inbound security rules`
3. Add a rule allowing HTTP port `80`
4. Use a priority lower than default deny rules, such as `100`
5. Save

### What to observe
- Lower priority number means higher priority
- Default rules exist automatically
- Allowing a port in NSG is not enough if the VM firewall or app is not listening

### 5. Create Two VNets and Peer Them

Steps:
1. Create `vnet-app-dev` with address space `10.20.0.0/16`
2. Open `vnet-practice-dev`
3. Select `Peerings`
4. Add peering to `vnet-app-dev`
5. Allow virtual network access
6. Save

### What to observe
- Address spaces must not overlap
- Peering is used for private VNet-to-VNet communication

### 6. Review Private Endpoint Concept

Practice safely without creating extra cost-heavy resources:
1. Open a storage account
2. Go to `Networking`
3. Review `Private endpoint connections`
4. Review how private endpoint setup asks for VNet, subnet, and private DNS integration

### What to observe
- Private endpoints place a private IP in your VNet
- DNS must resolve the service name to the private IP for private access to work

### 7. Clean Up

Steps:
1. Delete VNet peering connections
2. Delete NSGs if not needed
3. Delete VNets
4. Delete the full practice resource group if all labs are complete

## Troubleshooting Checklist

- Confirm the resource is in the expected VNet and subnet
- Check NSG inbound and outbound rules
- Check VM operating system firewall
- Confirm route tables if custom routes are used
- Validate DNS resolution
- Check load balancer or application gateway health probes
- Confirm private endpoint DNS configuration

## Common Interview Questions

- What is a VNet?
  Answer:
  A VNet is a private network in Azure used to connect and isolate Azure resources.

- What is the difference between NSG and Azure Firewall?
  Answer:
  NSG provides basic traffic filtering at subnet or NIC level. Azure Firewall is a centralized managed firewall with advanced filtering and logging capabilities.

- What is the difference between Load Balancer and Application Gateway?
  Answer:
  Load Balancer works at Layer 4 for TCP and UDP traffic. Application Gateway works at Layer 7 for HTTP and HTTPS web traffic and can provide WAF features.

- What is the difference between Private Endpoint and Service Endpoint?
  Answer:
  Service Endpoint secures access to supported Azure services while still using the service public endpoint. Private Endpoint gives the service a private IP inside your VNet.

- What is VNet peering?
  Answer:
  VNet peering connects two Azure VNets privately through the Azure backbone, as long as their address spaces do not overlap.

## Final Tip

For networking interviews, explain traffic flow step by step: source, destination, port, NSG, route, firewall, DNS, and target service health.
