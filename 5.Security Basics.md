# Security Basics

This file covers the security basics that are important before going deeper into Azure identity, RBAC, Key Vault, network security, and production access control. These topics help you understand how systems protect users, applications, data, and infrastructure.

## 1. Authentication vs Authorization

Authentication and authorization are two of the most important security concepts.

### Authentication
- Authentication verifies who a user or application is
- Example:
  entering a username and password, using MFA, or logging in with a certificate

### Authorization
- Authorization decides what the authenticated identity is allowed to do
- Example:
  a user can log in to Azure but may only have read access to one resource group

### Why this matters
- A user can be successfully authenticated but still not have permission to access a resource
- Many access issues are authorization problems, not login problems

### Interview point
- Authentication answers "Who are you?"
- Authorization answers "What are you allowed to do?"

## 2. RBAC Concepts

RBAC stands for Role-Based Access Control.

### What RBAC does
- Assigns permissions based   roles
- Gives users, groups, service principals, or managed identities access to resources
- Helps avoid giving unnecessary permissions

### Common RBAC terms
- Principal:
  The identity receiving access, such as a user, group, or application
- Role:
  A set of permissions, such as Reader, Contributor, or Owner
- Scope:
  The level where access is assigned, such as subscription, resource group, or resource

### Common Azure roles
- Reader:
  Can view resources but cannot make changes
- Contributor:
  Can create and manage resources but cannot grant access to others
- Owner:
  Has full access, including permission to assign roles

### Why this matters
- RBAC is heavily used in Azure access management
- Incorrect RBAC assignments are a common reason users cannot perform actions

## 3. Secret Management

Secrets are sensitive values that should not be exposed.

### Examples of secrets
- Passwords
- API keys
- Database connection strings
- Certificates
- Tokens

### Good secret management practices
- Do not store secrets in source code
- Store secrets in a secure vault
- Rotate secrets regularly
- Give access only to identities that need it
- Audit secret access where possible

### Azure example
- Azure Key Vault is used to securely store and manage secrets, keys, and certificates

### Why this matters
- Exposed secrets can lead to data loss, unauthorized access, and production incidents
- Interviewers often ask how pipelines and applications should handle passwords or keys

## 4. Encryption at Rest and in Transit

Encryption protects data by making it unreadable without the correct key.

### Encryption at rest
- Protects data stored on disks, databases, storage accounts, or backups
- Example:
  data stored in Azure Storage or Azure SQL

### Encryption in transit
- Protects data while it moves across a network
- Example:
  HTTPS traffic between a browser and a web application

### Why this matters
- Data should be protected both when stored and when transmitted
- Production systems should avoid sending sensitive data over plain HTTP

### Interview point
- At rest means stored data
- In transit means data moving between systems

## 5. Least Privilege Principle

Least privilege means giving only the minimum access required to perform a task.

### What it means
- Users should not receive admin access unless they truly need it
- Applications should only access the resources required for their function
- Temporary elevated access is better than permanent high privilege

### Why this matters
- Reduces the damage if an account or application is compromised
- Improves security and compliance
- Makes access easier to review and control

### Example
- A monitoring user may only need Reader access, not Contributor or Owner access
- A deployment pipeline may need access only to a specific resource group, not the full subscription

## 6. MFA Basics

MFA stands for Multi-Factor Authentication.

### What MFA does
- Requires more than one proof of identity
- Usually combines something you know, something you have, or something you are

### Examples
- Password plus mobile approval
- Password plus OTP code
- Password plus hardware security key

### Why this matters
- MFA reduces the risk of account compromise
- It is commonly required for admin and privileged accounts

## 7. Common Security Mistakes

Security issues often come from simple mistakes.

### Common mistakes
- Giving Owner access when Reader is enough
- Storing passwords in scripts or Git repositories
- Disabling MFA for admin users
- Sharing one account between multiple people
- Leaving public access enabled unnecessarily
- Not reviewing permissions regularly

### Interview point
- Good security is not only about tools
- It also requires careful access design, monitoring, and regular review

## Common Interview Questions

- What is the difference between authentication and authorization?
  Answer:
  Authentication verifies who the user or application is. Authorization decides what that identity is allowed to access or change after signing in.

- What is RBAC?
  Answer:
  RBAC stands for Role-Based Access Control. It is a way to assign permissions using roles, identities, and scopes. In Azure, RBAC controls who can access subscriptions, resource groups, and resources.

- What is the principle of least privilege?
  Answer:
  Least privilege means giving users or applications only the minimum permissions required to complete their task. This reduces security risk if an account is misused or compromised.

- Why should secrets not be stored in code?
  Answer:
  Secrets in code can be accidentally exposed through Git, logs, screenshots, or shared files. They should be stored in a secure secret manager such as Azure Key Vault.

- What is the difference between encryption at rest and encryption in transit?
  Answer:
  Encryption at rest protects stored data, such as files, disks, backups, and databases. Encryption in transit protects data while it moves between systems, such as HTTPS traffic.

- Why is MFA important?
  Answer:
  MFA adds another layer of protection beyond a password. Even if a password is stolen, the attacker still needs the second factor to sign in.

- What would you check if a user can log in but cannot access an Azure resource?
  Answer:
  First confirm the user is authenticated, then check RBAC role assignments, scope, group membership, deny assignments, and whether the user is accessing the correct subscription or resource group.

- What are examples of sensitive secrets?
  Answer:
  Passwords, API keys, database connection strings, certificates, and access tokens are common examples of secrets.

## Final Tip

Do not study security only as definitions. Practice explaining access problems step by step: who is signing in, what role they have, at what scope, and whether they really need that level of access.
