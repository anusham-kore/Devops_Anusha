# Azure Databases

Azure database services store application data using managed relational, NoSQL, cache, and analytics-friendly options. For interviews, focus on choosing the right database, backup, high availability, scaling, and security.

## 1. Azure SQL Database

Azure SQL Database is a managed relational database service based on Microsoft SQL Server.

### Used for
- Web application databases
- Business applications
- Relational data with tables and SQL queries
- Applications that need managed backups and high availability

### Interview point
- Azure SQL Database is PaaS, so Microsoft manages the database platform, patching, backups, and high availability features.

## 2. Azure SQL Managed Instance

Azure SQL Managed Instance provides near full SQL Server compatibility with managed service benefits.

### Used for
- Migrating existing SQL Server workloads
- Applications needing SQL Server Agent or instance-level features
- Lift-and-shift database migrations

### Interview point
- Choose Managed Instance when Azure SQL Database is too limited for an existing SQL Server application.

## 3. Cosmos DB

Azure Cosmos DB is a globally distributed NoSQL database service.

### Used for
- Low-latency applications
- Global applications
- JSON document data
- High-scale workloads
- Flexible schema data

### Interview point
- Cosmos DB is commonly chosen when applications need global distribution, high scale, and low latency.

## 4. Database Backup and Restore

Managed Azure database services provide built-in backup options.

### Important concepts
- Point-in-time restore
- Long-term retention
- Geo-restore
- Automated backups
- Recovery testing

### Interview point
- Backup is useful only if restore is tested.

## 5. High Availability

High availability keeps databases available during platform or infrastructure failures.

### Common options
- Zone redundancy
- Geo-replication
- Failover groups
- Read replicas
- Built-in managed backups

## 6. Choosing the Right Database

| Requirement | Good Choice |
| --- | --- |
| Relational SQL application | Azure SQL Database |
| Existing SQL Server migration | Azure SQL Managed Instance |
| Globally distributed NoSQL data | Cosmos DB |
| Shared cache/session data | Azure Cache for Redis |
| PostgreSQL application | Azure Database for PostgreSQL |
| MySQL application | Azure Database for MySQL |

## Hands-On Practice

Use `rg-practice-dev` and choose low-cost settings.

### 1. Create an Azure SQL Database

Steps:
1. Search for `SQL databases`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. Database name: `sqldb-practice-dev`
5. Create a new SQL server
6. Choose a region close to you
7. Select a low-cost compute option for practice
8. Select `Review + create`
9. Create the database

### What to observe
- Azure creates a logical SQL server and database
- Server firewall rules control access
- You do not manage the SQL Server VM or OS

### 2. Configure Firewall Access

Steps:
1. Open the SQL server
2. Select `Networking`
3. Add your client IP if you need to connect from your laptop
4. Save

### What to observe
- Authentication alone is not enough if network access is blocked
- Firewall rules are a common connection issue

### 3. Review Backup Settings

Steps:
1. Open the SQL database
2. Review `Backups`
3. Check point-in-time restore options
4. Review retention settings

### What to observe
- Managed backups are available without manually creating backup jobs
- Retention affects recovery options and cost

### 4. Create a Cosmos DB Account

Steps:
1. Search for `Azure Cosmos DB`
2. Select `Create`
3. Choose `NoSQL`
4. Resource group: `rg-practice-dev`
5. Account name: unique name
6. Region: nearby region
7. Choose free tier if available
8. Create the account

### What to observe
- Cosmos DB is account-based
- You create databases and containers inside the account
- Partition key design is important for scale

### 5. Clean Up

Steps:
1. Delete the SQL database if no longer needed
2. Delete the SQL server if it was created only for practice
3. Delete the Cosmos DB account
4. Confirm no database resources remain

## Common Interview Questions

- What is the difference between Azure SQL Database and SQL Managed Instance?
  Answer:
  Azure SQL Database is a managed database service for modern applications. SQL Managed Instance gives more SQL Server instance-level compatibility for migrations.

- When would you choose Cosmos DB?
  Answer:
  Choose Cosmos DB for globally distributed NoSQL workloads that need high scale, flexible schema, and low latency.

- What should you check if an application cannot connect to Azure SQL?
  Answer:
  Check server name, credentials, firewall rules, private endpoint or network configuration, database status, and connection string.

## Final Tip

Database interview answers should mention data model, scale, latency, availability, backup, and security.
