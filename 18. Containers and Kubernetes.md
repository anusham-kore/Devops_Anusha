# Containers and Kubernetes

Containers package applications with dependencies, and Kubernetes orchestrates containers at scale. For Azure interviews, focus on Docker basics, Azure Container Registry, AKS architecture, pods, deployments, services, ingress, scaling, and secrets.

## 1. Docker Basics

Docker builds and runs containers.

### Key terms
- Image:
  A packaged application and dependencies
- Container:
  A running instance of an image
- Dockerfile:
  Instructions to build an image
- Registry:
  Stores container images

## 2. Container Registry

A container registry stores and distributes images.

### Examples
- Docker Hub
- Azure Container Registry
- GitHub Container Registry

## 3. Azure Container Registry

Azure Container Registry, or ACR, is Azure's managed private container registry.

### Used for
- Storing private images
- Integrating with AKS
- Image scanning integrations
- Build and deployment pipelines

## 4. AKS Architecture Basics

AKS is Azure Kubernetes Service.

### Main parts
- Control plane:
  Managed by Azure
- Node pool:
  Worker VMs running containers
- Pods:
  Smallest deployable unit
- Services:
  Stable network access to pods
- Ingress:
  HTTP and HTTPS routing into the cluster

## 5. Pods, Deployments, and Services

### Pod
- Runs one or more containers
- Has an IP address inside the cluster
- Usually managed by a deployment

### Deployment
- Manages replicas
- Supports rolling updates
- Recreates pods if they fail

### Service
- Provides stable access to pods
- Common types: ClusterIP, NodePort, LoadBalancer

## 6. Ingress

Ingress manages HTTP and HTTPS traffic into Kubernetes.

### Used for
- Host-based routing
- Path-based routing
- TLS termination
- Central web entry point

## 7. Scaling and Upgrades

### Scaling options
- Scale pods using replicas
- Horizontal Pod Autoscaler
- Cluster autoscaler
- Scale node pools

### Upgrade areas
- Kubernetes version
- Node image
- Application image version

## 8. Secrets and ConfigMaps

### ConfigMap
- Stores non-secret configuration

### Secret
- Stores sensitive values in Kubernetes
- Should be integrated with Key Vault for stronger production security

## Hands-On Practice

AKS can create cost. Use a small cluster only for practice and delete it immediately after.

### 1. Create an Azure Container Registry

Steps:
1. Search for `Container registries`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. Registry name: globally unique name
5. SKU: `Basic`
6. Region: nearby region
7. Create the registry

### What to observe
- ACR stores container images privately
- AKS can pull images from ACR when permissions are configured

### 2. Create a Small AKS Cluster

Steps:
1. Search for `Kubernetes services`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. Cluster name: `aks-practice-dev`
5. Region: nearby region
6. Node size: choose a small size
7. Node count: 1 for practice
8. Integrate with ACR if available
9. Create the cluster

### What to observe
- Azure manages the control plane
- Worker nodes appear in a managed resource group
- AKS requires networking, identity, and node pool configuration

### 3. Connect to AKS

Command:

```bash
az aks get-credentials --resource-group rg-practice-dev --name aks-practice-dev
kubectl get nodes
```

### 4. Deploy a Sample App

Command:

```bash
kubectl create deployment nginx-demo --image=nginx
kubectl expose deployment nginx-demo --type=LoadBalancer --port=80
kubectl get pods
kubectl get service nginx-demo
```

### What to observe
- Deployment creates pods
- Service exposes pods
- LoadBalancer service creates an Azure load balancer public IP

### 5. Scale the Deployment

Command:

```bash
kubectl scale deployment nginx-demo --replicas=3
kubectl get pods
```

### What to observe
- Kubernetes creates more pod replicas
- If nodes do not have capacity, scheduling can fail

### 6. Clean Up Kubernetes Resources

Command:

```bash
kubectl delete service nginx-demo
kubectl delete deployment nginx-demo
```

### 7. Delete AKS and ACR

Steps:
1. Delete the AKS cluster
2. Delete the ACR if created only for practice
3. Confirm the managed resource group was removed
4. Check Cost Management

## Common Interview Questions

- What is the difference between image and container?
  Answer:
  An image is the packaged application. A container is a running instance of that image.

- What is AKS?
  Answer:
  AKS is Azure's managed Kubernetes service. Azure manages the control plane, while you manage worker nodes, workloads, networking, and security configuration.

- What is the difference between pod, deployment, and service?
  Answer:
  A pod runs containers. A deployment manages pod replicas and updates. A service provides stable network access to pods.

- What is ACR?
  Answer:
  Azure Container Registry is a managed private registry for storing container images.

## Final Tip

For AKS interviews, explain the flow: build image, push to ACR, deploy to AKS, expose with service or ingress, monitor, scale, and secure secrets.
