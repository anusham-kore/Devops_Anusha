# Azure Storage

Azure Storage provides scalable cloud storage for files, objects, messages, NoSQL-style data, logs, and backups. For interviews, understand storage account types, redundancy, access tiers, security, and common troubleshooting points.

## 1. Storage Accounts

A storage account is the top-level Azure resource for Azure Storage services.

### A storage account can contain
- Blob containers
- File shares
- Queues
- Tables

### Important properties
- Name must be globally unique
- Region controls where data is stored
- Redundancy controls how data is replicated
- Networking controls public or private access

## 2. Blob Storage

Blob Storage stores unstructured object data.

### Used for
- Images and videos
- Backups
- Logs
- Documents
- Static website content
- Data lake scenarios

### Blob types
- Block blobs:
  Common files and objects
- Append blobs:
  Logging scenarios
- Page blobs:
  Disk-like workloads

### Interview point
- Blob Storage is used for object storage, not SMB file shares

## 3. Azure Files

Azure Files provides managed file shares using SMB and NFS.

### Used for
- Shared application files
- Lift-and-shift file shares
- Mounting shares on Windows or Linux
- Replacing basic on-premises file servers

### Interview point
- Azure Files is the right choice when applications need a shared file path

## 4. Queue Storage

Queue Storage stores messages for asynchronous processing.

### Used for
- Decoupling application components
- Background processing
- Passing work items to workers

### Interview point
- Queues help one part of an application send work without waiting for another part to finish immediately

## 5. Table Storage

Table Storage is a NoSQL key-value store.

### Used for
- Simple structured data
- Large volumes of lightweight records
- Low-cost key-value storage

### Interview point
- Table Storage is not a relational database

## 6. Access Tiers

Blob access tiers control storage cost and access cost.

### Hot
- Frequently accessed data
- Higher storage cost
- Lower access cost

### Cool
- Infrequently accessed data
- Lower storage cost
- Higher access cost

### Archive
- Rarely accessed data
- Lowest storage cost
- Data must be rehydrated before access

## 7. Redundancy Options

Redundancy protects data against hardware, datacenter, or regional failures.

### Common options
- LRS:
  Locally redundant storage inside one datacenter
- ZRS:
  Zone-redundant storage across availability zones
- GRS:
  Geo-redundant storage to a secondary region
- RA-GRS:
  Read-access geo-redundant storage

### Interview point
- LRS is cheaper but less resilient
- GRS protects against regional failure

## 8. Shared Access Signatures

A shared access signature, or SAS, grants limited access to storage without sharing account keys.

### SAS can control
- Allowed service
- Allowed resource
- Permission such as read or write
- Start and expiry time
- IP range
- Protocol

### Interview point
- Use SAS for limited temporary access, not permanent broad access

## 9. Storage Security

### Security controls
- Disable anonymous public access where possible
- Use private endpoints for private network access
- Restrict firewall rules
- Use Entra ID authentication where supported
- Rotate keys if account keys are used
- Use least privilege access

## Hands-On Practice

Use resource group `rg-practice-dev`.

### 1. Create a Storage Account

Steps:
1. Search for `Storage accounts`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. Name: globally unique lowercase name
5. Region: same as practice resources
6. Performance: `Standard`
7. Redundancy: `LRS`
8. Create the account

### What to observe
- Storage account names are globally unique
- Redundancy is selected during creation and can affect cost

### 2. Create a Blob Container

Steps:
1. Open the storage account
2. Select `Containers`
3. Select `+ Container`
4. Name: `demo`
5. Public access level: `Private`
6. Create

### What to observe
- Private containers require authenticated access
- Public access should be avoided unless there is a clear requirement

### 3. Upload and Download a Blob

Steps:
1. Open the `demo` container
2. Upload a small file
3. Select the uploaded blob
4. Download it from the portal

### What to observe
- Blob properties show URL, size, type, and access tier
- The URL may exist, but private access prevents anonymous download

### 4. Generate a SAS Token

Steps:
1. Open the uploaded blob
2. Select `Generate SAS`
3. Allow only `Read`
4. Set a short expiry time
5. Generate SAS URL
6. Test the SAS URL in a browser

### What to observe
- SAS grants temporary access
- After expiry, the SAS URL should stop working

### 5. Create an Azure File Share

Steps:
1. Open the storage account
2. Select `File shares`
3. Select `+ File share`
4. Name: `sharedev`
5. Create
6. Upload a small test file

### What to observe
- File shares are different from blob containers
- File shares can be mounted by supported clients

### 6. Review Networking Settings

Steps:
1. Open the storage account
2. Select `Networking`
3. Review public network access and firewall settings
4. For practice, avoid locking yourself out unless you understand private access

### 7. Clean Up

Steps:
1. Delete uploaded files if no longer needed
2. Delete the storage account or full practice resource group
3. Confirm no unused storage accounts remain

## Common Interview Questions

- What is the difference between Blob Storage and Azure Files?
  Answer:
  Blob Storage is object storage for unstructured data. Azure Files provides managed file shares that can be mounted using SMB or NFS.

- What are Azure Storage redundancy options?
  Answer:
  Common options include LRS, ZRS, GRS, and RA-GRS. They define how data is replicated within a datacenter, across zones, or to another region.

- What is a SAS token?
  Answer:
  A SAS token provides limited, time-bound access to storage resources without sharing the storage account key.

- What is the difference between hot, cool, and archive tiers?
  Answer:
  Hot is for frequently accessed data, cool is for infrequently accessed data, and archive is for rarely accessed data that can tolerate retrieval delay.

## Final Tip

For storage interviews, always mention data type, access pattern, security requirement, and redundancy requirement before choosing a storage service.
