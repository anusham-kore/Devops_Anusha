# Azure Governance

Azure governance helps organizations control cost, security, compliance, ownership, and resource standards. For interviews, focus on policy, tags, locks, management groups, and cost management.

## 1. Azure Policy

Azure Policy enforces or audits rules for Azure resources.

### Used for
- Restricting allowed regions
- Requiring tags
- Auditing public IP usage
- Enforcing SKU standards
- Controlling resource configuration

### Interview point
- Azure Policy is used for governance at scale, not for user authentication.

## 2. Resource Locks

Resource locks prevent accidental deletion or modification.

### Lock types
- Delete:
  Resource can be read and modified, but not deleted
- Read-only:
  Resource can be read, but not modified or deleted

### Interview point
- Locks can protect critical resources but may block deployments if not planned.

## 3. Tags

Tags are key-value pairs used to organize resources.

### Common tags
- Environment
- Owner
- CostCenter
- Application
- Criticality

### Interview point
- Tags are useful for cost tracking, ownership, and automation.

## 4. Management Groups

Management groups organize subscriptions and apply governance at higher levels.

### Used for
- Large organizations
- Policy assignment across subscriptions
- Access control hierarchy
- Environment separation

## 5. Cost Management

Azure Cost Management helps track and control cloud spend.

### Tools
- Cost analysis
- Budgets
- Alerts
- Advisor recommendations
- Tag-based reporting

## 6. Naming Standards

Naming standards make resources easier to identify and manage.

### Example
- `rg-app-dev-cin`
- `vnet-app-prod-cin`
- `stappdev001`

## Hands-On Practice

Use practice resources only.

### 1. Add Tags to a Resource Group

Steps:
1. Open `rg-practice-dev`
2. Select `Tags`
3. Add `Environment = Dev`
4. Add `Owner = YourName`
5. Save

### What to observe
- Tags help identify ownership and environment
- Tags can be used in cost reports

### 2. Create a Budget

Steps:
1. Search for `Cost Management`
2. Select your subscription
3. Open `Budgets`
4. Create a small monthly practice budget
5. Add email alert thresholds
6. Save

### What to observe
- Budgets do not stop resources automatically
- Budgets alert you when spending reaches thresholds

### 3. Assign a Built-In Policy

Steps:
1. Search for `Policy`
2. Select `Assignments`
3. Assign a built-in policy such as requiring a tag
4. Scope it to a practice resource group or subscription
5. Review compliance after some time

### What to observe
- Policy can audit or deny resource creation
- Scope controls where policy applies

### 4. Add a Delete Lock

Steps:
1. Open a practice resource group
2. Select `Locks`
3. Add lock name: `lock-delete-practice`
4. Lock type: `Delete`
5. Save

### What to observe
- Delete operations are blocked until the lock is removed
- Locks are useful for critical resources

### 5. Clean Up

Steps:
1. Remove the resource lock before deleting resources
2. Remove test policy assignments
3. Delete test budgets if no longer needed
4. Delete practice resources

## Common Interview Questions

- What is Azure Policy?
  Answer:
  Azure Policy audits or enforces rules for resources, such as required tags, allowed regions, or allowed SKUs.

- What are resource locks?
  Answer:
  Resource locks prevent accidental deletion or modification of important resources.

- Why are tags important?
  Answer:
  Tags support cost tracking, ownership, automation, and resource organization.

## Final Tip

Governance is about control at scale: who can create what, where resources can exist, how cost is tracked, and how critical resources are protected.
