# Backup, Disaster Recovery, and High Availability

Backup, disaster recovery, and high availability protect workloads from accidental deletion, hardware failures, datacenter issues, and regional outages. For interviews, focus on RPO, RTO, backup, restore, replication, and failover design.

## 1. Azure Backup

Azure Backup protects data and workloads using managed backup services.

### Can protect
- Azure VMs
- Files and folders
- SQL Server workloads
- Azure Files
- On-premises workloads with agents

### Interview point
- Backup protects against data loss and accidental deletion, but restore must be tested.

## 2. Recovery Services Vault

A Recovery Services Vault stores backup and recovery metadata.

### Used for
- Azure Backup
- Azure Site Recovery
- Backup policies
- Recovery points

## 3. Azure Site Recovery

Azure Site Recovery replicates workloads for disaster recovery.

### Used for
- VM replication
- Region-to-region DR
- On-premises to Azure DR
- Planned and unplanned failover

### Interview point
- Backup restores data; Site Recovery helps fail over workloads.

## 4. RPO and RTO

### RPO
- Recovery Point Objective
- Maximum acceptable data loss
- Example: lose no more than 15 minutes of data

### RTO
- Recovery Time Objective
- Maximum acceptable downtime
- Example: restore service within 1 hour

### Interview point
- RPO is about data loss; RTO is about downtime.

## 5. Business Continuity

Business continuity keeps critical services running during failures.

### Design areas
- Backup strategy
- DR region
- DNS failover
- Database replication
- Monitoring and alerting
- Runbooks and testing

## 6. Zone and Geo Redundancy

### Zone redundancy
- Protects against datacenter or zone failure inside a region

### Geo redundancy
- Protects against regional failure by replicating to another region

## Hands-On Practice

Use a test VM only. Backup and DR resources can create cost, so clean up carefully.

### 1. Create a Recovery Services Vault

Steps:
1. Search for `Recovery Services vaults`
2. Select `Create`
3. Resource group: `rg-practice-dev`
4. Name: `rsv-practice-dev`
5. Region: same as your VM
6. Create the vault

### What to observe
- The vault is used to manage backup configuration
- Vault region matters for protected resources

### 2. Configure VM Backup

Steps:
1. Open the Recovery Services Vault
2. Select `Backup`
3. Workload location: `Azure`
4. Workload type: `Virtual machine`
5. Choose a backup policy
6. Select a test VM
7. Enable backup

### What to observe
- Backup policy controls frequency and retention
- First backup may take time

### 3. Run Backup Now

Steps:
1. Open the protected VM in the vault
2. Select `Backup now`
3. Choose retention date
4. Start backup

### What to observe
- Recovery points are created from backup jobs
- Backup status can be monitored from the vault

### 4. Review Restore Options

Steps:
1. Open the protected VM backup item
2. Select `Restore VM`
3. Review restore point selection
4. Do not complete restore unless needed

### What to observe
- Azure can restore a full VM or disks depending on scenario
- Restore planning is part of DR readiness

### 5. Review Site Recovery

Steps:
1. Open the Recovery Services Vault
2. Select `Site Recovery`
3. Review replication options
4. Do not enable replication unless you are ready for cost and cleanup

### 6. Clean Up

Steps:
1. Stop backup for the test VM
2. Delete backup data if no longer needed
3. Delete the Recovery Services Vault
4. Confirm no protected items remain

## Common Interview Questions

- What is the difference between backup and disaster recovery?
  Answer:
  Backup protects data and allows restore. Disaster recovery focuses on bringing workloads online in another location after a major failure.

- What is RPO?
  Answer:
  RPO is the maximum acceptable amount of data loss.

- What is RTO?
  Answer:
  RTO is the maximum acceptable downtime before service must be restored.

- What is Azure Site Recovery?
  Answer:
  Azure Site Recovery replicates workloads and supports failover for disaster recovery.

## Final Tip

Do not say "we have backup" as the full answer. Mention restore testing, retention, RPO, RTO, monitoring, and documented failover steps.
