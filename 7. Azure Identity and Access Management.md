1. Microsoft Entra ID (Azure AD)

Microsoft Entra ID is Microsoft’s cloud-based identity provider.

What it does
Authenticates users and applications
Manages identities across cloud and on-premises
Enables Single Sign-On (SSO)
Interview point
Entra ID handles authentication
2. Users, Groups, and Roles
Users
Individual identities (employees, admins)
Groups
Collection of users
Used to assign permissions efficiently
Roles
Define allowed actions
Best practice
Assign roles to groups, not directly to users
3. Role-Based Access Control (RBAC)

RBAC controls authorization in Azure.

Components
Security Principal (User / Group / App)
Role Definition (Reader, Contributor, Owner)
Scope (MG → Sub → RG → Resource)
Common roles
Owner
Contributor
Reader
Interview point
RBAC = what you can do
4. Conditional Access

Policy-based access control.

Example
Require MFA if login from unknown location
Conditions
User / group
Location
Device
Application
5. Managed Identities

Used for secure service-to-service authentication.

Types
System-assigned
User-assigned
Use case
VM accessing Key Vault without storing secrets
6. Service Principals

Identity for applications and automation.

Used in
Jenkins
Terraform
CI/CD pipelines
Interview point
App identity with credentials
7. Multi-Factor Authentication (MFA)

Adds extra security during login.

Example
Password + OTP
8. Privileged Identity Management (PIM)

Provides temporary admin access.

Example
Admin gets access for 1 hour only
🧪 Hands-On Practice
1. Create a User in Entra ID

Steps:

Go to Azure Portal
Search Microsoft Entra ID
Select Users
Click New user
Enter username and details    #jenkins: Puto318146
Create                        #test: Vuqa589259
Observe
User is created in directory
Can be used for login
2. Create a Group and Add User

Steps:

Go to Groups
Click New group
Type: Security
Add created user
Create
Observe
Group simplifies access management
3. Assign RBAC Role

Steps:

Go to Resource Group
Click Access control (IAM)
Click Add role assignment
Select role: Reader
Assign to group
Save
Observe
User inherits permissions via group
4. Enable MFA

Steps:

Go to Entra ID → Users
Select user
Enable MFA (via security settings)
Observe
Login requires additional verification
5. Create Service Principal (CLI)
az ad sp create-for-rbac --name my-app
Observe
Outputs client ID, secret, tenant ID
Used for automation
6. Enable Managed Identity (VM)

Steps:

Go to VM
Select Identity
Enable system-assigned
Save
Observe
Identity created automatically
No secrets needed

💡 Interview Flow (Very Important)
User/App → Entra ID (Authentication) → RBAC (Authorization) → Conditional Access + MFA
✅ Final Tip
Authentication = who you are
Authorization = what you can do
Always use groups + managed identities in real projects
